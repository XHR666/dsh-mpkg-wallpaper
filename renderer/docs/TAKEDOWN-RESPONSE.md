# TAKEDOWN-RESPONSE —— 72 小时响应模板与执行清单

> **用途**：当**权利人**（或其代理 / 平台转达 / 律师函）对本仓库的**任何材料**提出**删除、澄清、署名或下架**要求时，
> 直接照本文执行。**不辩论、不拖延、不要求对方先举证**。
> **总原则（写进 `docs/COPYING-RULES.md` §9.11 的硬承诺）**：**先删后议** —— 默认 **72 小时内**移除被主张范围，
> **不等**法律定性，**不先**要求对方证明；即使我们认为要求有误，**删除仍然执行**，之后再另行沟通恢复条件。
> **另一条硬承诺**：**绝不"被发现了才偷偷删"** —— 任何删除都**必须公开留痕**。
> **日期**：2026-09-17 · **落点**：`docs/TAKEDOWN-RESPONSE.md` · **不是法律意见**；涉及金额/和解/反通知的答复**必须先经律师**。

## 0. 触发与时限（收到即开始计时）

| 触发形式 | 起算 | 首响时限 | 完成移除时限 |
|---|---|---|---|
| 邮件 / GitHub Issue / Discussions 里的**权利人主张** | 收到时刻（记录时间戳） | **24 小时内**回执 | **72 小时内**完成移除（含衍生内容） |
| 平台转达（GitHub / npm 的 DMCA 或政策通知） | 通知到达时刻 | **按平台时限**（通常 24h 内回应，**取更短者**） | 同上 |
| 律师函 | 收到时刻 | **4 小时内**告知用户 + 暂停相关发布 | 72 小时内移除，**答复文本由律师出** |
| 作者/上游**变更许可或收紧条款**（非主张，但影响我们） | 发现时刻 | 评估 24h 内 | 视结论：整改或移除，**同样留痕** |

> **不确定时按最严处理**：分不清"主张"还是"询问"⇒ 先按主张走（先下架、再澄清）。**宁可多删，不可迟删。**

## 1. 角色与第一动作（别在群里讨论，先执行）

| 角色 | 谁 | 第一动作 |
|---|---|---|
| **响应负责人** | 项目所有者（用户） | 建立**单一**对外沟通渠道；**不**在公开场合争论法律定性 |
| **执行** | 本仓库维护会话/代理 | 按 §3 清单执行删除与留痕，**每一步留命令与 sha256** |
| **复核** | 第二人（另一会话/代理） | 按 §5 复验"删干净 + 门禁绿 + 留痕在位" |
| **法律** | 律师 | 只有律师能对外作出法律承诺；**答复文本先过律师** |

**收到主张后的 5 个动作（顺序固定）**：

1. **冻结**：暂停任何正在进行的发布（npm `publish`、Pages 部署、打 tag/Release）；
2. **回执**：24h 内回一封**不改立场**的确认信（模板 §6.1）—— 只说"已收到、已暂停分发、正在移除，会在 X 前回复"；
3. **定位**：把被主张对象映射到 §3 的删除范围（**含衍生内容**）；
4. **移除**：执行 §3 + §4 留痕；
5. **复验**：按 §5 出证据包，再决定"是否恢复/如何恢复"（恢复**必须**先得律师意见）。

## 2. 证据记录（从第一分钟开始，格式固定）

建一个**不公开**的证据目录（放仓库外，例如 `../Delete/takedown-<YYYYMMDD>/`），按下列表格逐行填：

| 字段 | 内容 | 例 |
|---|---|---|
| `received_at` | 收到时刻（含时区） | `2026-09-20T11:04+08:00` |
| `channel` | 渠道（邮件 / GitHub Issue #123 / 平台通知 ID） | `GitHub Issue #141` |
| `claimant` | 主张方（**公开留痕里只写"权利人/其代理"**，不公开其隐私信息） | `权利人（信息存档，不公开）` |
| `claim` | 主张原文（**逐字存档**，含附件名/hash） | `…` |
| `objects` | 被主张对象清单（我们映射后的路径 + sha256） | 见 §3 表 |
| `ack_sent_at` | 回执发出时刻 | |
| `removed_at` | 移除完成时刻（逐项） | |
| `public_notice_url` | 公开留痕的 URL（§4） | |
| `counsel` | 律师是否已介入（是/否 + 日期） | |
| `outcome` | 结论（已删除 / 部分恢复 / 保持删除） | |

**硬要求**：① 主张原文**逐字**存档（不改写、不摘要替代）；② 每个被删文件**删前**记 `sha256`（用于日后恢复与对照）；
③ **不公开**主张方的个人信息（邮箱、真实姓名、地址）。

## 3. 删除范围：**含衍生内容**（漏一项就等于没删干净）

> **原则**：不只删"被主张的那一个文件"，**所有由它派生的东西一起处理** —— 否则等于换个地方继续分发。

| # | 类别 | 典型落点（本仓库实例） | 处理 |
|---|---|---|---|
| 1 | **原件本体** | `assets/fonts/<file>`、`vendor/<x>/**`、`demo/**`、`shaders/*.h` | **移出仓库**（不是 `rm`：移入 `../Delete/takedown-<date>/`，保留可恢复副本） |
| 2 | **二进制/构建产物** | `demo.html`、`core/we-scene-bundle.js`（bundle 里可能内联了 shader/资源）、`package-baseline.json` 等打包清单 | 重新生成（`node tools/...`/`build-pages.mjs`），**不手工编辑**；重新生成后核对不含被删材料 |
| 3 | **测试用例与夹具** | `tests/clean-room-*-test.mjs`、`tests/effects-corpus.mjs`、`tests/*-test.mjs` 里内联的期望值/语料、`tests/publish-check.mjs` 的清单 | 删除或**改写为不依赖该材料**；若测试本身引用了该材料 ⇒ 一并移除并在留痕里写明 |
| 4 | **文档引用** | `THIRD-PARTY.md`、`docs/COMPLIANCE-REVIEW.md`、`docs/REIMPLEMENTATION-STATEMENTS.md`、`docs/COPYING-RULES.md` §4 台账、`README.md`/`docs/README-PUBLIC.md` 的署名段 | **不删历史记录**：加"**已移除（日期 + 原因 + 公开通知链接）**"标注，保证外部可核 |
| 5 | **诊断/上报字样** | `web/diag-flags.json`、`docs/README-DIAGNOSTICS.md`（若有该材料的开关/字样） | 同步清理，保持 `diag-flag-check` 双向一致 |
| 6 | **npm / Pages / 其它分发面** | npm 包（`npm unpublish` 或**补发新版本**——已发布版本无法真正撤回）、Pages 站点、`demo/**` 静态产物、镜像/缓存（CDN/搜索引擎按平台流程） | 逐面处理并记录；**npm 优先补发新版本**（不 `unpublish` 已成依赖的版本，避免破坏下游） |
| 7 | **对外表述** | 任何声称"已获授权 / 已洁净室 / 已结案"的句子 | **当场改口径**（未得律师意见前**不得**声称结案） |
| 8 | **分发副本** | 工作区里的 `.bak-*`、`archive/`、`reports/` 里的旧快照 | 一并清出分发面（`publish-check` 的 `.gitignore.public` 规则要覆盖） |

**执行顺序**：**先**停分发（§1-1）→ **再**删仓库内容（1–3）→ **再**改文档表述（4、7）→ **最后**处理外部分发面（6）。
**任何一步都先记 sha256，再动手。**

## 4. 公开留痕（**必做**，且要"外面看得见"）

**两处同时留痕**（缺一不可）：

1. **GitHub Issue**（标题固定格式，便于检索）：`[takedown] <对象> 已移除 — <YYYY-MM-DD>`
   - 正文**只写**：① 收到了什么性质的要求（**不公开主张方隐私信息**）；② 我们**主动**移除了什么（路径清单 + 提交号）；
   ③ **时间**（收到 / 完成移除）；④ **范围**（含衍生内容，逐类说明：测试、文档、产物）；
   ⑤ 恢复条件（若将来可恢复，写明"需律师意见 + 上游许可确认"）。
   - **不写**：法律论证、对主张方的评价、可能被解读为承认或否认责任的表述（这部分只在律师渠道里谈）。
2. **专用页面**：`docs/REMOVALS.md`（本仓库，**新建**）—— 一份"删除/移除记录"的**累积**页面，
   与 `docs/PATCHES.md` 的分工是：`PATCHES.md` 记工程变更，`REMOVALS.md` 记**因合规/权利人要求而移除**的东西。
   - 每行字段固定：`日期 | 对象（路径） | 性质（主动收口 / 权利人要求 / 上游许可变更） | 范围（含衍生内容） | 公开通知链接 | 恢复条件`。

> **为什么必须公开**：这是对 `docs/COPYING-RULES.md` §9.11"**不偷偷删除**"的兑现 —— 外部（含未来读者、
> 潜在贡献者、权利人）能验证"我们什么时候删了什么、为什么"。**删除动作本身不需要保密，主张方的身份需要。**

## 5. 主动联系主张方（不要等对方追问）

| 时机 | 动作 | 模板 |
|---|---|---|
| 移除完成后 **≤72h** | 回一封**完成通知**：已移除的对象、范围、时间、后续不再分发的承诺、可选的"联系渠道" | §6.2 |
| 若主张方**要求超出我们能力**（例如要求删除我们自写的等价实现） | **不独自拒绝**：说明已按主张移除原文材料，其余部分需律师评估，给出**明确回复期限** | §6.3 |
| 若我们**认为主张有误**（例如对象是公开标准公式） | **先删**，再以"希望澄清"的姿态提供证据（标准名称 + 章节），**不要求对方先撤回** | §6.4 |
| 恢复时 | **先**取得律师意见 + 上游许可确认，**再**以书面形式告知主张方，并在 §4 的两处留痕里记"已恢复（依据）" | §6.5 |

## 6. 模板（复制即用；**对外文本必须先过律师**）

### 6.1 回执（24h 内，收到即发）

```text

我们已于 <YYYY-MM-DD HH:MM TZ> 收到您关于 <对象概述> 的通知。

我们预计在 <YYYY-MM-DD>（不超过 72 小时）前完成移除，并会在完成后再次告知您移除范围。

<署名>
```

```text
主题：[<仓库名>] 移除已完成 — <YYYY-MM-DD>

公开留痕：<Issue URL>、<REMOVALS 页面 URL>

后续我们不会再分发上述材料。若您认为仍有遗漏，请告知，我们会在 72 小时内处理。

<署名>
```

### 6.3 超出范围时的答复

```text
主题：[<仓库名>] 关于 <对象> 的移除范围

您好：

您通知中指向的原文材料已按 §（上一封）移除完毕。
对于 <被要求但非原文的部分，例如：我们自写的等价实现 / 公开标准公式>，

<署名>

如您仍认为需要进一步处理，请告知；我们尊重您的判断。

<署名>
```

## 8. 复验证据包（"删干净"的机器判据）

```bash
cd "$(git rev-parse --show-toplevel)"      # 仓库根（= we-scene-demo）
# ① 仓库里不再有被删材料的残留（逐对象跑；把 <pattern> 换成文件名/标识符）
grep -rIn --binary-files=without-match "<pattern>" . | grep -v '^./\.git/' || echo "0 残留 ✓"
# ② 文档/门禁仍一致（期望 rc=0）
node tests/docs-check.mjs
# ③ 发布闸门 0 阻塞；带 WE 资产根时只允许出现 REVIEWED 行（附证据引用）
node tests/publish-check.mjs
# ④ 公开留痕可访问（Issue + REMOVALS 页面）
#    curl -sI <issue-url> | head -1 ; curl -sI <pages-url>/docs/REMOVALS.md | head -1
```

**复验通过的定义**：① 每个被删对象在**代码、测试、文档、产物**四处都 0 命中（文档里只允许存在
"已移除"的历史标注，且该标注**不含**被删材料的内容）；② 两份门禁 rc=0 / 0 阻塞；③ 两处公开留痕可访问；
④ 证据目录（仓库外）里 `claim` 原文、sha256、时间戳齐全。
