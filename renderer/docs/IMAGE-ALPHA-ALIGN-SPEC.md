## 1. `coerceImageAlphaMode(raw)` —— 图像 alpha 量纲归一化

### 1.1 要解决的问题（调用方需求）

WE 场景文件里的层不透明度字段 `alpha` 在**同一个字段名**下混用两种量纲：

- **单位量纲**：`0 … 1`，`1` = 完全不透明。
- **百分比量纲**：编辑器属性面板对用户暴露 `0 … 100`，用户直接写在场景里时会出现
  `50` 这种"想表达 0.5"的值。

渲染管线的着色器只接受单位量纲。因此**建层**与**脚本/属性绑定改 alpha**两条路径都必须在
进入管线前做一次量纲归一。这个归一必须**幂等**（单位量纲再跑一次不变），因为两条路径
可能先后都跑。

`alpha` 字段还可能是**非数值**：缺省（字段不存在）、`null`、属性绑定对象
`{user:"属性名", value:默认值}`、关键帧动画对象 `{animation:{…}, value:…}`、字符串。
建层调用点已经先用 `typeof === 'number'` 过滤，非数值一律**不进入**本函数而是交给默认值 `1`；
但**脚本绑定路径**可能把任意值喂进来，所以本函数自身必须对非数值有确定行为。

### 1.2 输入域与取值

| 输入类别 | 具体取值 | 说明 |
|---|---|---|
| 非有限/非数值 | `NaN`、`±Infinity`、字符串、`null`、`undefined`、布尔、对象、数组 | 函数自身不抛异常 |
| 负数 | `< 0` | 编辑器允许出现（脚本可用负值做过冲） |
| 零 | `+0`、`-0` | 两者必须都归到 `+0` |
| 单位区间 | `0 < v ≤ 1` | 原样通过 |
| 百分数区间 | `1 < v ≤ 100` | 除以 100 后落入单位区间 |
| 超上限 | `> 100` | 饱和到 `1` |

### 1.3 判定与返回值（真值表）

设 `UNIT_MAX = 1`、`PERCENT_MAX = 100`（**具名常量**，实现里不得裸写这两个字面量）。

| 条件 | 返回 | 备注 |
|---|---|---|
| `!Number.isFinite(raw)` | `0` | 非数值一律当"完全透明"，不留 NaN 进管线（NaN 会污染后续矩阵/颜色） |
| `raw > UNIT_MAX` 且 `raw ≤ PERCENT_MAX` | `raw / PERCENT_MAX` | **必须是除法**（除以字面常量 100），不是乘以倒数 —— 见 §1.5 |
| `raw > PERCENT_MAX` | `1` | 饱和 |
| 其余（有限且 `raw ≤ UNIT_MAX`） | `raw < 0` → `0`；`raw === -0` → `+0`；否则 `raw` | |

**逐位精度要求**：上表对任意 IEEE-754 double 输入都必须与本节给出的算式**逐位相同**，
包括 `-0` 的符号。这是硬要求：alpha 会逐层乘进最终颜色，1 ULP 的差异会破坏
`PATCHES.md` 记录的 RMSE 基线与 `diag-flag-check` / 逐位回归门禁。

### 1.4 边界与默认（必须逐条覆盖的用例）

| # | 输入 | 期望 | 为什么 |
|---|---|---|---|
| 1 | `undefined` / `null` | `0` | **注意**：建层路径的默认 `1` 由调用点给，不在本函数内 —— 本函数只对"明确传进来的值"负责 |
| 2 | `NaN` | `0` | 非有限 |
| 3 | `Infinity` / `-Infinity` | `0` / `0` | 非有限（`-Infinity` **不**走负数分支） |
| 4 | `'0.5'`（字符串） | `0` | `Number.isFinite` **不做**字符串强转 |
| 5 | `true` / `{}` / `[]` / `[0.5]` | `0` | 同上 |
| 6 | `-1` / `-0.0001` | `0` | 负数饱和 |
| 7 | `-0` | `+0`（`Object.is(v, 0)` 为真） | 零符号必须归正 |
| 8 | `0` | `0` | |
| 9 | `0.5` | `0.5`（逐位） | 单位量纲直通 |
| 10 | `1` | `1` | `1` **不**进百分数分支（条件是严格 `>`） |
| 11 | `1.0000000000000002` | `0.010000000000000002` | 刚过 1 即按百分数 |
| 12 | `1.5` | `0.015` | 真语料外的代表值 |
| 13 | `50` | `0.5` | 百分数量纲 |
| 14 | `100` | `1` | 百分数上界，除法后正好 1 |
| 15 | `100.5` / `101` / `1e9` | `1` | 超上限饱和 |
| 16 | 幂等：对 #9–#14 的输出再调一次 | 逐位不变 | 两条调用路径可能连跑 |

### 1.5 为什么"除以 100"不能改写成"乘以 0.01"

`0.01` 不是二进制可精确表示的数。`x * 0.01` 与 `x / 100` 是两次不同的舍入
（后者对精确可表示的除数做正确舍入，前者先引入 `0.01` 自身的表示误差），
在 `1 < x ≤ 100` 内**存在取值使两者差 1 ULP**。
本仓库有逐位回归门禁，"看起来等价"的改写会造成假红。⇒ 规格**钉死除法**。

### 1.6 不得做什么

- 不得把 `[0,1]` 的 clamp 挪到调用点（有 3 个调用点，漏一个就是 NaN/越界进管线）。
- 不得对字符串做 `Number()` 强转（会改变 `'0.5'`、`''`、`'  '`、`'abc'` 的结果）。
- 不得引入 `console` 输出或异常。

## 2. `alignmentOffsetForToken(alignment, w, h)` —— 对齐 token → 像素偏移

### 2.1 要解决的问题（调用方需求）

WE 场景里每个层的 `alignment` 决定"`origin` 落在这一层的哪个位置"：

- `alignment = center`（缺省）时 `origin` 就是**几何中心**；
- `alignment = left` 时 `origin` 落在**左边缘中点**，于是真正的几何中心要从
  `origin` 往右挪半个宽度；
- 依此类推。渲染前必须把这个"枢轴 → 实绘中心"的位移算出来，加到层变换里。

既有测试 `alignment-test.mjs` ①/②/③ 已经把这张符号表钉死为本仓库的对外契约
（③ 还用真包 `3660962877` 的 27 个非 center 层做过矩形差对账）。

### 2.2 token 文法

`alignment` 在场景文件里是**小写英文单词的拼接串**（真机语料实测取值见 §2.5）。
文法按"**子串包含**"而不是"精确等于"解析：

```
alignment ::= <任意值>            // 场景里最常见的形态是字符串；缺省 → 调用点填 'center'
横向分量 ∈ { 含 "left" , 含 "right" , 都不含 }
纵向分量 ∈ { 含 "top"  , 含 "bottom"," 都不含 }
```

**为什么是子串而不是精确枚举**：组合 token（`bottomleft` / `topleft` / `topright` /
`bottomright`，以及理论上任意顺序的 `lefttop`、`bottomleft…`）在场景里真实存在，
而枚举表会随组合数爆炸。子串判定同时天然容忍**多余空白**（`' left '` 命中 `left`）。

### 2.3 轴、方向与返回值

返回值是**二元数组** `[ox, oy]`，单位 = 与 `w`/`h` 同量纲的像素，坐标系为
**y-up 编辑器空间**（`parseScene` 之后的下游会在绘制期做一次 y 取反，
`compositeLayer` 与 `preview.mjs` 都已按此约定接好）。

| token 命中 | 轴 | 方向 | 偏移 |
|---|---|---|---|
| `left` | x | 正 | `+w/2` |
| `right` | x | 负 | `-w/2` |
| `top` | y | 负 | `-h/2` |
| `bottom` | y | 正 | `+h/2` |
| 两轴都未命中 | — | — | 该分量为 `0` |

**语义**：`origin` 是枢轴，实绘中心 = `origin + 偏移`；`left` 的枢轴在左边缘，
所以中心要 `+w/2`。`top` 在 y-up 空间里是上边缘 ⇒ 中心要往下 ⇒ `-h/2`。

### 2.4 短路、优先级与兜底（**必须逐条覆盖**）

| # | 情形 | 行为 | 依据 |
|---|---|---|---|
| 1 | `alignment === undefined` | `[0,0]` | 建层前缺省（调用点也会填 `'center'`，两条都要成立） |
| 2 | `alignment === null` | `[0,0]` | 同上，`null` 单独判（`String(null)='null'` 不含任何 token，行为一致但必须短路，避免无谓字符串化） |
| 3 | `alignment === 'center'`（**精确相等**） | `[0,0]` | 缺省值 |
| 4 | `'centerleft'` 这类**含 center 但不等于** center 的串 | **不短路**，按子串继续 → `+w/2` | 精确相等才短路；这是既有行为，不是 bug |
| 5 | 未知 token（`'middle'`、`'foo'`、`''`、`'0'`） | `[0,0]` | 不认识就当 center（不抛异常） |
| 6 | **大小写**：`'LEFT'` / `'Left'` / `'Center'` | `[0,0]`（`'Center'` 也 `[0,0]`） | token 匹配**大小写敏感**；`'LEFT'` 不是合法 token |
| 7 | 多余空白：`' left '`、`'\tbottom\n'` | 正常命中 | 子串判定天然容忍 |
| 8 | **同一轴两个 token 都命中**（`'leftright'`、`'topleftbottomright'`…） | x 轴 **`left` 优先**；y 轴 **`top` 优先** | 既有行为：同轴是**互斥择一**，不是叠加 |
| 9 | 非字符串：数字 `0`、布尔 `true`、对象、数组 | 先 `String()` 再按上面规则；`['left']` → `+w/2`，`{}` → `[0,0]` | 属性绑定可能把非字符串喂进来 |
| 10 | 组合 token | 两轴**各自独立**相加：`bottomleft` → `[+w/2, +h/2]`；`topleft` → `[+w/2, -h/2]` | ③ 语料层已验证 |
| 11 | 负 `w`/`h`（层被负 scale 镜像） | 偏移方向随之翻转：`left` + 负宽 → `-w/2` | 调用方传的是**有符号**的 `size×scale`；等价于局部矩阵 `T(align)` 内乘负 `S` |
| 12 | `w`/`h` 非数值（`undefined`） | `undefined/2 = NaN` → 该分量 `NaN` | **不额外兜底**：这是调用方的契约违反，静默兜底会掩盖几何 bug |

### 2.5 真机语料实测取值（6 个真包，作为回归夹具的事实来源）

| 包 id | `alignment` 实测值（出现次数） |
|---|---|
| `3326873240` | 缺省 ×58、`right` ×3、`left` ×1 |
| `3327063360` | 缺省 ×65、`right` ×3、`left` ×1 |
| `3544152633` | 缺省 ×66、`bottomleft` ×1、`right` ×1、`left` ×2 |
| `3554161528` | 缺省 ×37 |
| `3660962877` | 缺省 ×100、`bottom` ×25、`bottomleft` ×1、`top` ×1 |
| `3719111841` | 缺省 ×43 |

> 复现：`node -e` 或 `clean-room-alpha-align-test.mjs` 的 ④ 段（该测试会把这 6 个包的
> 全部原始取值打出来，并逐个与对照实现比对）。
> **语料里没有 `right`+`left` 同轴并存、也没有大写 token** —— 这些只出现在 §2.4 的合成用例里。

### 2.6 不得做什么

- 不得把同轴两 token 改成"叠加"（那会改变 `'leftright'` 的结果）。
- 不得把 `center` 的短路改成 `includes('center')`（会改变 `'centerleft'`）。
- 不得为了"表驱动"而引入一张 `token → (轴, 方向)` 的外部常量表再循环累加 ——
  那正是本次要消除的结构形态。本规格要求的是**先解析出两轴各自的符号，再组装**。

## 3. 与调用点的契约（重写时不可破坏）

| 调用点 | 现状 | 重写后必须 |
|---|---|---|
| `parseScene` 建层 | `alpha: coerceImageAlphaMode(typeof o.alpha === 'number' ? o.alpha : 1)` | 非 number → 常量 `1`（**不是** 0），number → 归一化 |
| 绑定写入 | `l.alpha = coerceImageAlphaMode(n)`；`n` 来自 `numOf(v)`，可能为 `null` → 调用点已 `return false` 挡掉 | 不变 |
| `compositeLayer` | `const off = alignZero ? [0,0] : alignmentOffsetForToken(layer.alignment, w, h)`，随后 `translate(m, off[0], -off[1], 0)` | 不变；`?align=0` 诊断开关仍然整段跳过 |
| `preview.mjs` / `parity-check.mjs` / `layer-rect-check.mjs` / `alignment-test.mjs` | `lib.imageAlignmentOffset(...)` | **改名后同步更新**（导出名变更属于本次重写的差异点之一） |
