### 2.3 「发散」的输入：本层的唯一运动来源

本层发射器 `speedmin/speedmax` 都是 0（def 里没写）⇒ 初速**只**来自 `turbulentvelocityrandom`。我们的实现（冻结点 `:3770-3783`）：

```js
case 'turbulentvelocityrandom': {
  const smin = pGetVal(pr, 'speedmin', 0), smax = pGetVal(pr, 'speedmax', 0)
  const amp = smin + rng() * (smax - smin)
  if (amp) {
    // ①(P-131 批 D) …音频响应…相位乘 (1+env)
    const a = p.random * Math.PI * 2 * (1 + (audioEnv || 0)) + (p.pos[0] + p.pos[1]) * 1e-3
    p.vel = [Math.cos(a) * amp, Math.sin(a) * amp, 0]        // ★ 方向 = p.random 抽的独立随机角
  }
  p.turbSeed = p.random * 1000
  break
}
```

* `p.random = rng()`（出生时抽一次，冻结点 `spawnParticle` 的 `:3663` `random: rng(),`）⇒ **每颗粒子一个 0..2π 的独立随机方向**，幅度 250 px/s。
* `(p.pos[0]+p.pos[1])*1e-3` 这一项名义上让方向随位置变，但发射半径只有 5px ⇒ 相位只变 ~0.005 rad，
  **空间相干性实际为零**。
* def 里的 `scale: 0.1`（官方=噪声场的空间频率）、`timescale: 0.5`、`offset`、`forward/right`、`phasemin`
  **一个都没读**（`grep -n "turbulentvelocityrandom" -A16` 的片段里只有 `speedmin/speedmax` 被消费）。
* 代码注释自己写着这是**近似**：`// 官方是"沿 curl 噪声场走 duration 秒后的方向"；这里用确定性伪噪声近似`
  —— 但「沿 curl 噪声场」= **方向的函数是位置**（同地同向），现在写成了**每颗粒子独立**，这不是"近似"，是**换了语义**。

## §4 最小改法提案（含风险与"先做档位再改默认"）

### 4.1 改哪一行

`core/we-scene-bundle.js` 的 `applyInitializer` → `case 'turbulentvelocityrandom'`（冻结点 `:3770-3783`）。
把「方向 = `p.random` 抽的随机角」换成「**方向 = 当前位置的函数**」（官方：curl 噪声场；三个独立参考实现都按位置采样）：

```js
// spawnParticle（不新增/不移动任何 rng() 调用）：p.turbT = sys._scaledT
case 'turbulentvelocityrandom': {
  const smin = pGetVal(pr, 'speedmin', 0), smax = pGetVal(pr, 'speedmax', 0)
  const amp = smin + rng() * (smax - smin)                       // ← 仍然只抽这一次（RNG 流不变）
  if (amp) {
    const k = PTURB_K                                             // 相干频率（≈1/500px）；?pturb=legacy ⇒ 走旧代码
    const z = (p.turbT || 0) * pGetVal(pr, 'timescale', 1) + (p.random * pGetVal(pr, 'phasemax', 0))
    const s = p.pos[0] * k, t2 = p.pos[1] * k
    const n1 = Math.sin(s * 3.1 + t2 * 1.7 + z) * Math.cos(t2 * 2.3 - z)   // 与既有 turbulence operator 同形的确定性场
    const n2 = Math.cos(s * 2.3 - t2 * 2.9 + z) * Math.sin(s * 1.9 + z)
    const m = Math.hypot(n1, n2) || 1
    p.vel = [n1 / m * amp, n2 / m * amp, 0]                       // ★ 改这一行：方向随位置走，不随 p.random 走
  }
  p.turbSeed = p.random * 1000
  break
}
```

**为什么这样最小**：
* **RNG 流一个字节都不动**（`amp` 的那次 `rng()` 位置不变、次数不变）⇒ 只有**用到了这条 initializer 的层**会变
  （语料 200 个可解析 def 的粒子层里 **28 层**：rope 13 / sprite 14 / spritetrail 1，见 §5）；
* `timescale` 让"不同出生时刻的方向"随仿真时间缓慢转动 ⇒ 形成**一缕弯的烟**（而不是一条直棍），
  与官方 stock 预设 "Vapor (double)" 的观感一致；
* 场形状直接复用本仓库 `turbulence` operator 已有的确定性 sin/cos 场（冻结点 `:4124`）
  ⇒ initializer 与 operator **共用一个场**，物理自洽，且不引入新依赖、不抄任何 GPL 代码。

### 4.2 步进建议：**先档位、再默认**

1. **第一步（本批）**：`PTURB_K` 取一个"足够相干"的常数（反证里 `0.002` ≈ 500px 已经把段长总和从 6796px 打到 309px），
   并**同时**加逃生开关 `?pturb=legacy`（回旧随机角）。
   ⚠ **开关要登记**：`web/diag-flags.json` 现在是**脚本生成**的、`tests/diag-flag-check.mjs` 断言"代码 153 == README 主表 153"，
   所以新增这一个 flag 必须在**同一个提交**里：改代码 + 改 `docs/README-DIAGNOSTICS.md` 主表 + 重跑 `node diag-flag-check.mjs` 重新生成 json，
   否则门禁直接红（不是放宽，是数量对不上）。
2. **第二步（真机 A/B 之后）**：拿官方 `preview.gif`/官方 WE 画面对比 `?pturb=legacy` 与默认两档；
   若"烟"的走向/手性不对，**第一刀砍 `PHASEMAX/场的相位**，第二刀才谈 `scale` 的真实量纲。
3. **不要**顺手改 `one_per_frame`（§3.8-1 已证浏览器里不封顶、去掉只会让线更长）。
4. **不要**把 `subdivision`（Catmull-Rom）或 `children`（子系）塞进这一批 —— 前者只改平滑度，后者是**另一个功能缺口**
   （"(double)" 的第二股烟目前完全不画），都会把这次的单变量验证搅浑。

### 4.3 风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| **场频率（`PTURB_K`）是未证实量** | 三个参考实现的"scale 量纲"互相冲突（MIT 用 `pos*scale`、lwe-ref 把 0.1 **硬编码**、wer-ref 是 curl 走步），我们**没有**官方二进制可对拍 ⇒ 相干长度只能"大到能消掉乱线"，具体值靠真机观感定 | `?pturb=legacy` 随时回退；报告 §6 明写未证实 |

| y 手性 | 作者空间 y-up、渲染 y-down（本仓库 `velocityrandom`/`movement.gravity` 同族都要翻） | 反证里 `n2` 已取 `-`；真机看"烟往上还是往下飘"再定 |

### 4.4 用户可以立刻用的零改动应急开关

## §6 未证实项

1. **官方湍流场的真实公式/量纲（最重要）**：我们只证到"方向必须是位置的函数、相干长度 ≳200px 才能消掉乱线"。
