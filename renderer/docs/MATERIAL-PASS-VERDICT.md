## 2. 代码路径（只读走查）

- 消费点：`core/we-scene-bundle.js:4024` —— `const mp = (mj.passes && mj.passes[0]) || {}`（只取第 0 个）。
- 与之并列的另一条路（**效果链**）**已经是遍历**：`:3996` `const scPass = (effect.passes && effect.passes[ejPassIdx]) || {}`
  按 `ejPassIdx` 逐个 pass 走 ⇒ 说明"多 pass 需要逐个走"这件事在本仓**已有实现范式**，只是**材质层未接**。
- 影响面：材质层只取 `[0]` ⇒ 若出现 `passes.length > 1` 的档，**第 1 个之后的 pass 会被整条跳过**（少画）。

## 3. 结论与判据

### 3.1 结论

**维持现状：不为材质层多 pass 改造渲染路径**（当前语料 0 命中 ⇒ 改与不改在本语料上**可观测等价**）。

理由：
1. **一手语料实测**：154 包 / 202 材质，`passes>1` = **0**（最大 1）⇒ 无实际收益，且任何改造都带来新的绘制序风险。
2. **范式已在仓内**：效果链已按 `ejPassIdx` 遍历 pass（`:3996`）⇒ 将来真要接材质层，改法有现成参照，**不需要现在猜**。
3. **改动风险不对称**：材质层多 pass 的语义（同一几何多次绘制？各自独立 blend/深度？pass 间依赖？）
   在**没有样本**的情况下无法验证 ⇒ 现在改属于"无证据改造"。

### 3.2 翻案判据（满足任一条即重新打开）

| # | 触发条件（可操作判据） | 动作 |
|---|---|---|
| **A** | 语料（或用户提供的新档）出现 **`passes.length > 1`** 的 `materials/*.json` | 按效果链范式（`:3996`）把材质层改为逐个 pass 走，并加回退口 `?matpass=legacy`（只走 `[0]`）+ 判据 |
| **B** | 真机对照出现"**某层少画了一半**"且该层材质 `passes>1` | 同上（并以该档为回归样本） |
| **C** | 上游/官方行为证据表明材质多 pass 有**跨 pass 状态依赖**（如第 2 个 pass 读第 1 个的 RT） | 先补语义再实现，不得只循环绘制 |
