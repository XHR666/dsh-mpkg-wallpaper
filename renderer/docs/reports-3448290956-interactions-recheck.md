## 2. 增量读数（该报告未覆盖、工具新给出）

- **补充①（口径区分，重要）：`嘴巴` 的"渲染原点"和"脚本原点"差一个祖先锚点。** 全包唯一附件层是
  `左眼白`（id 377，att=`Attachment`，父=头位置 179），锚点直算值 **[−16.022, +242.816]（y-up）**。
  `嘴巴` 是 `左眼白` 的后代 ⇒ 含锚合成原点 (1905.667, 1576.550) = 无锚 (1921.689, 1819.366) +
  Δ(−16.022, −242.816)。该报告 §5.1 引的 "(1921.7, 1819.4)" 是**无锚口径**（`layer-rect-check --noattach`
  同款）；它不影响"脚本读局部原点"的结论（脚本门面读 authored 值），但做**像素级对位**时应该用含锚口径
  —— 否则面部部件的期望位置会整体差 (−16, −243) 设计单位（≈ −51 屏幕像素）。
- **补充②：`嘴巴.scale` 脚本的解剖读数**：827 字符、导出 `update/init`、兜底值 `"1.00000 1.00000 1.00000"`、
  无层名引用。解码沙箱对它如实标 `⚠顶层中断` —— 因为顶层 `createScriptProperties()` 在纯 Node 沙箱里
  没有桩（这与 P-239 修的"压缩 import 编译失败"不同族：这条是**沙箱缺门面**，不是数据/编译缺陷）；
  该报告 §5.1 的三档反解用的是真机 raw 读数，不受此影响。
- **补充③：工具对"压缩 import"的容错**。`主发` 等 `import*as WEMath from'WEMath'`（P-239 同款压缩形态）
  的脚本，工具在进解码沙箱前剥掉 import 行 ⇒ 字符串表解码不再整条落空（`tests/layer-anatomy-test.mjs`
  的 27 条冻结判据里有该路径的回归钉）。
