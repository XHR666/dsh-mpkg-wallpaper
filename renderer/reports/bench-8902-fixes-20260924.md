#### ⑥ 追修（2026-09-25）：shim 的"首帧"判据本身是**假信号**，而且会抢走画布上下文
* **真机读数**（有头 Firefox + llvmpipe，`/webloader/?shell=0&id=<真壁纸>`；探针 = 在页面任何脚本之前
  给 `HTMLCanvasElement.prototype.getContext` 套一层**透传**记录器，只记录、原样 call through）：
  * `t≈141ms`：注入的 shim（`#mpw-noshell-frame`）对 `#sc` 调了 `getContext('webgl2')`（**无参数**）。
    **同一个 canvas 只有第一次调用生效** ⇒ 渲染器 `t≈544ms` 的 `lib.glCanvasAttrs()` 被静默顶掉，
    整页实际跑在浏览器默认值上：`alpha:true / antialias:true / premultipliedAlpha:true /
    preserveDrawingBuffer:false`（应为 `false/false/false/true`）。
  * `t≈151ms`：同一段探针就置了 `data-mpw-frame=1` —— 判据是"canvas 取得到上下文"，而 `#sc` 是静态
    `<canvas>`（默认 300×150），第一帧 rAF 就成立；**真首帧在 12s 之后** ⇒ 父页那层黑幕形同虚设。
* **改后**：shim 的首帧判据只读渲染器自己写的**被动**标记（`window.__mpwFirstFrame` 真首帧 / 视频首个

  **一个 `getContext` 都不调**；等不到就**不置位**，由父页 12s 兜底并如实计 `timeouts`（不假装出了帧）。
  同批修掉同类：`?video=` / `?type=video` 两条纯视频入口此前不置 `__mpwFirstFrame`（只有 `MPW-NOSCENE`
  那条置）⇒ 7s 看门狗 / `mpw-cap` / 预览握手上看到的都是"没有首帧"；现三处共用
  `mpwMarkVideoFirstFrame()`（只由 primary 写全局，口径与场景路径一致）。
* **改后读数（2026-09-25 实跑）**：密采样 180 次（≈12ms 间隔）=
  `{"armedSamples":180,"armVeilPairs":39,"earlyReveal":0,"maxVeilRun":39,"shellVisibleSamples":0}`；
  `B2d` 记录 = `[{t:616,type:webgl2,hasAttrs:true,alpha:false,premultipliedAlpha:false,antialias:false,
  preserveDrawingBuffer:true},…]`（预览 URL 带 `shell=0`，`#mpw-noshell` 在）。
* **判据**：`A6a1`（shim 源码里 `getContext` 命中 0 次）、`A6a2`（三个被动信号都在）+ 浏览器
  `B2b`（改成 **≈12ms 密采样**：黑幕生命期是秒级，固定采样点靠碰运气 ⇒ 这条之前既假过也假红过）、

## 5. 追加项 E（富文本"同一张图展示两遍"）

1. **真测试台复现**（`allwallpaper/dd/3660962877/project.json`，66 个属性；本机语料实测）：
   `img` token **39 个**、唯一 URL **7 个**、其中**一条 URL 出现 33 次**（33 个属性名的文案里**逐字节相同**）；
   另一份 `0923/2902406982`：16 个 token，同一 URL 9 次。
   **真面板读数**（浏览器，`__benchPatch.propsImages()`，两个真语料条目都测了）：
   | 条目 | 档位 | img token | 实际渲染 `<img>` | duplicatesSkipped | 最大重复组 |
   |---|---|---|---|---|---|
   | `3660962877` | `?propimg=all`（改前行为） | 38 | **38** | 0 | — |
   | `3660962877` | 缺省 `once` | 38 | **6** | **32** | 同一条 URL 出现 33 次 → 只画 1 次 |
   | `3326873240` | `?propimg=all` | 13 | **13** | 0 | — |
   | `3326873240` | 缺省 `once` | 13 | **6** | **7** | 同一条 URL 出现 8 次 → 只画 1 次 |
   （`rendered` 少于唯一 URL 数是因为面板还会按既有隐藏名单藏掉一部分行，不影响"同一 URL 只画一遍"这条判据：
   `once.rendered == report.groups.length` **恒成立**，判据就这么写的。）
2. **去重键的判定**（三条候选，全部有实测）：
   * ① **归一化后的整条 URL**（scheme/host 小写、去 fragment、去默认端口，**不碰 query**）—— **采用**；
   * ② `host+path` —— **否决**：真语料里 `m.qpic.cn/psc` 一个 path 下挂着 **6 张不同**的图（身份在 query），
     按它归并会把 6 张压成 1 张（比原 bug 更糟）；判据 `D6` 钉住"两条不同的 query 必须不同 key"；
   * ③ "去掉 size 类参数后再比" —— 本语料 **0 命中**（14 个多图条目里没有任何一对只差 size 参数）⇒ 不引入不可判定规则。
   同理**否决**"长公共前缀"归并：那 6 张图的 query 共享 `…/TmEUgtj9EK6.7V8ajmQrE` 前缀。
3. **哪种重复该去、哪种该留**（读数对照）：
   * **去**：同一条 URL 在**同一趟渲染**里出现多次（`once` 档：33→1、9→1；`mode=row` 档跨行不去重 ⇒ 又变回 33，
     这就是"改回去必红"的对照）；
   * **留**：**不同 URL** 的有意重复（分隔图 `fengefu000…004` 这种）—— 规则按 URL 判定 ⇒ 5 张分隔图仍是 5 张（判据 `5h`）；
   * **压掉**："已经画成图的那张图又作为**链接**出现"（判据 `5f`：`linksSuppressed=1`，锚文本是别的 URL 的链接**不动**，`5g`）。
4. **档位**：`?propimg=once`（缺省，用户要的）/ `row`（旧语义，行内去重）/ `all`（完全不去重，对照排障）。
5. **判据**：纯函数层 `tests/bench-props-text-test.mjs` 的 `5a–5k` + 变异自证 `D4/D5/D6`（全过）；
   真面板侧探针 `__benchPatch.propsImages()`（rendered / srcs / naturalWidth / 去重账本 / links），
   浏览器 `B7/B7a` 给出 `once` 与 `all` 的成对读数。
6. **歧义（转给主线）**：若用户想要的是"同一张**画面**但 URL 不同（尺寸/水印变体）也只显示一遍"，
   那需要**按图像内容**判定（下载后比对像素/哈希），而不是按 URL —— 本轮的语料里**没有**这种样本，
   强行按前缀归并会误伤（见 2.②）。我按"同一 URL 只画一遍 + 同图链接不再重复"实现，等用户确认是否要更进一步。

## 8. 「8899 → 8902 合并方案」（可照着做）

**现状（改前）**
* `:8899` = 渲染器页 + `/bundle.js` `/core/**` `/shaders/**` `/elysia/**` `/pkg/<id>` `/project/<id>` `/diag` `/report` `/baseline`…
* `:8902` = 测试台静态面 + `/api/**` + `/media/dev/**` + `/web/dev/**` + `/diag`(环形缓冲) + `/report` + `/baseline`；
  渲染器面靠 `/webloader/**` **反代**到 `:8899`（另有一份"渲染器根路由"名单 `RENDERER_ROOT_ROUTES` 也反代）。
* 痛点：必须同时起两个服务；库根切换在 `:8899` 侧不生效（→ PKG 404）；预览要先加载 8899 的整页外壳。

**目标**：只开 `:8902`，`http://127.0.0.1:8902/` 就能用当前库根测壁纸；`/webloader/**` 旧路径行为等价；上游可选。

**已落地的步骤（照这个做即可）**
1. **抽实现**（`server/we-scene-demo-server.mjs`）：
   * 把 `http.createServer(async (req,res)=>{…})` 的**整段函数体**提成 `const serverHandler = async (req, res) => {…}`，
     并 `export const rendererRequestHandler = serverHandler`（逐字搬迁，不改任何路由的响应）；
   * `listen` 只在"本文件是进程入口"时发生（`process.argv[1]` realpath 比对）⇒ `import` 它不会再抢 8899 端口；
   * 顶层 `await import(pkgExtract)` 改成**失败即降级**（原因记进 `pkgParserUnavailable()`），
     否则宿主 `:8902` 会因为"这台机器没有包解析器"直接起不来。
2. **库根唯一真源**：新增 `let libraryRootProvider`、`export function setLibraryRootProvider(fn)`、
   `export function currentLibraryRoot()`；把所有**按 id 解析**的读取点收口到它
   （`findScene()` 用它 + `/ddvideo` `/noise` `/transpiled` `/shader` `/project` `/type` 全部改经它）。
3. **宿主接线**（`server/we-scene-demo-server-8902.mjs`）：
   `import { rendererRequestHandler, setLibraryRootProvider } from './we-scene-demo-server.mjs'`；
   在 `activeRoot` 定义之后 `setLibraryRootProvider(() => activeRoot)`（**取值器**，不是快照）。
4. **本地直供**：`serveRendererLocal(req,res,url,relOverride)` 把 `req.url` 改写成渲染器路由空间里的路径
   （`/webloader/**` 去前缀；根路由原样）后调用 `rendererRequestHandler`，并写
   `X-Bench-Served: local`（有上游时另加 `X-Bench-Upstream: host:port`）；
   `/webloader/**` 与"渲染器自己的根路由"（`RENDERER_LOCAL_EXACT` + `RENDERER_LOCAL_PREFIXES`）都走它；
   **静态面优先**（`demo/` 里真有同名文件就不打扰渲染器处理器）。
5. **上游降级为可选**：`MPW_RENDERER_UPSTREAM`（新）/ `MPW_RENDERER_8899`（旧，兼容既有测试）；
   都不设 ⇒ 纯本地；设了但连不上 ⇒ **GET/HEAD 回退本地**（响应头带 `X-Bench-Upstream-Error`），
   只有"本地也没这条路由"才按老口径 502（既有 K2d 判据不变）。
6. **预览无外壳**：渲染器页支持 `?shell=0`（服务端注入隐藏外壳的样式 + 首帧握手）；
   测试台在本仓档自动补这个参数，并在首帧之前盖黑幕（`#bench-frame-veil`）。
7. **旧路径**：`/webloader/**` **保留**（等价，仍是本仓渲染器页；只是不再依赖 8899）。
   老脚本/书签零改动。

**风险与回退**
* 风险：`import` 8899 模块会执行它的模块级初始化（读环境、建包索引缓存）——已实测无副作用（不再 listen）；
* 风险：两处 `MPW_ROOT` 默认值必须一致（都用"仓库上一级"）——已一致；
* 回退：`MPW_RENDERER_UPSTREAM=http://127.0.0.1:8899` 并起 8899 ⇒ 立刻回到"反代优先"的老行为；
  彻底回退 = `git revert` 上述 4 个文件（不改动数据/语料）。
