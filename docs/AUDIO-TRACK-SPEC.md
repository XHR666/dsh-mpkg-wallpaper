# 音轨清单规格（AUDIO-TRACK-SPEC）

本文件是插件 `lib/pkg-extract.js` 中**音轨模块**的唯一实现依据。它是按公开容器格式资料
（RIFF/WAVE、FLAC、Ogg、ISO-BMFF、ID3v2、MPEG-1/2/2.5 Layer I–III、ADTS）与该模块的
**外部契约**重新写成的规格；实现只允许引用本规格，**不得**参照任何其它仓库/文件里的同功能代码。

> 洁净室（clean-room）用途：这份规格是"公共格式事实 + 本模块对外契约"的书面化。
> 来历与处置记录见 `THIRD-PARTY.md`。

词汇：
- **包**：`scene.pkg` / `.mpkg` 容器；其目录表给出条目 `path`、压缩后长度、原始长度、是否压缩。
- **松散源**：一个目录（`scene.json` + 素材文件），没有容器目录表。
- **条目头**：某条目开头的少量字节（本规格最多 16 字节）。
- **规格里的"必须/不得"**是给实现的硬约束；"建议"是实现自由。

---

## 1. 后缀清单（哪些文件算音频）

1.1 判定**只看路径最后一个小数点之后的部分**（"后缀"），ASCII 大小写不敏感；
没有小数点的路径一律不算音频。

1.2 后缀 ∈ 下表才算音频。表外的后缀（`.txt`、`.mp4`、`.tex`…）**不得**进入音轨清单，
即使 `scene.json` 的 sound 层引用了它。

| 后缀 | 兜底 MIME（§3 无命中时使用） |
|---|---|
| `mp3` | `audio/mpeg` |
| `ogg` | `audio/ogg` |
| `oga` | `audio/ogg` |
| `opus` | `audio/ogg` |
| `wav` | `audio/wav` |
| `flac` | `audio/flac` |
| `m4a` | `audio/mp4` |
| `aac` | `audio/mp4` |

1.3 兜底 MIME 表**只**用于"前缀字节不足以定容器"（§3 无命中）的情形；表里没有的后缀
不可能走到这一步（§1.2 已经把它们挡掉）。

1.4 §1.2 的表是**全仓库唯一的"后缀 → 音频 MIME"事实来源**：宿主路由（`lib/index.js` 的 `/raw`、
`/custom-media`、pkg 条目 `/media`、`/library-media`、`/custom-dir` 白名单、`/custom-folder`
前缀）一律经 `audioMimeFor` 或 `suffixAudioMime` 查这张表，**不得**再内联一份扩展名三元链
（历史缺陷：三份表漂移 ⇒ `.oga/.m4a/.aac` 在部分路由缺失、`/raw` 对音频一律
`application/octet-stream`）。表内 8 项与浏览器渲染器支持的后缀逐项一致。

1.5 后缀表的用途只在**过滤与兜底**（§1.2 决定"算不算音轨"）；容器判定（§3）本身**不看后缀**
——表外后缀的字节若命中 §3 规则，仍然返回该规则的 MIME，由调用方决定是否采用。

---

## 2. 路径规范化

2.1 收集前，每个路径字符串按顺序做两步规范化：
1. 反斜杠 `\` 全部换成 `/`（包内路径历史上出现过 Windows 分隔符）；
2. 若结果以 `./` 开头，**去掉这一层前缀**（只去一层：`./sounds/a.mp3` → `sounds/a.mp3`，
   而 `././sounds/a.mp3` → `./sounds/a.mp3`；中间或结尾的 `./` 不动）。

2.2 规范化后为空串的路径**丢弃**。

2.3 去重、排序、`refs` 全部以**规范化后**的路径为准。

---

## 3. 容器识别（按条目头定 MIME）

3.1 输入是条目开头的字节（实现读 16 字节即可；少于 16 字节时按实际长度判定，
**不得**因为"读得少"而改变结论——即判定只依赖前若干字节）。

3.2 规则按**下表自上而下**匹配，**第一条命中即返回**其 MIME；全部不命中返回空串 `''`
（调用方按 §1.2 兜底）。顺序是规格的一部分：

| # | 容器 | 条件（`b` = 头字节，`b[0]` 是第一个字节） | 返回 MIME |
|---|---|---|---|
| R1 | ISO-BMFF（MP4/M4A） | 偏移 4 起 4 字节 ASCII = `ftyp` | `audio/mp4` |
| R2 | RIFF/WAVE | 偏移 0 起 = `RIFF` **且** 偏移 8 起 = `WAVE` | `audio/wav` |
| R3 | Ogg | 偏移 0 起 = `OggS` | `audio/ogg` |
| R4 | FLAC（原生流） | 偏移 0 起 = `fLaC` | `audio/flac` |
| R5 | ID3v2 标签（通常是 MP3） | 偏移 0 起 = `ID3` | `audio/mpeg` |
| R6 | ADTS（AAC） | `b[0] == 0xFF` 且 `(b[1] & 0xF6) == 0xF0` | `audio/aac` |
| R7 | MPEG 音频帧同步 | `b[0] == 0xFF` 且 `(b[1] & 0xE0) == 0xE0` | `audio/mpeg` |

3.3 字节数不足的规则**跳过**（例如头只有 2 字节时 R1–R5 全部跳过，R6/R7 仍可命中）；
实现**不得**因为"长度不足"提前整体放弃（旧行为的"短于 12 字节一律返回空"**不在本规格内**）。

3.4 R6 必须排在 R7 之前：ADTS 的 `0xFFF1` 同时满足 R7 的位掩码，先判 R6 才能把它归为
`audio/aac`。这是本规格与"MPEG 同步优先"写法**唯一有意的行为差异**，其它输入下两者结论相同。

3.5 判定过程中任何异常（越界读、类型错误）都不得向上抛出：返回 `''`，由调用方按后缀兜底。

3.6 统一入口 `audioMimeFor(path, head)`（导出名，契约）——**"路径 + 头字节 → 音频 MIME"的唯一入口**：
1. 先按 §3 判定 `head`：命中即用该规则的 MIME；
2. §3 无命中 → 按 §1.2 的后缀兜底；
3. **唯一特例**：§3 命中 R5（`ID3`）**且**后缀兜底为 `audio/flac` ⇒ 返回 `audio/flac`。
   来历：真实语料里有带 ID3v2 标签前缀的 FLAC（标签长度可变，16 字节窗口里看不到 `fLaC`），
   按 R5 报 `audio/mpeg` 会让浏览器按 MP3 解码 FLAC 而失败 —— 这正是"扩展名 + 头字节双判"
   的用意：头字节判定优先，唯一例外交给后缀纠正。
4. 参数缺失 / 异常 / 表外后缀且 §3 无命中 ⇒ 返回 `''`（**不得**抛；调用方自行回落
   `application/octet-stream`）。
5. 引入本入口**不得**改变 §3.2 表的判定优先级（R1…R7 顺序、ADTS 先于 MPEG 同步）。

---

## 4. 条目收集与去重（包内 / 松散源同规则）

4.1 音轨集合 = **容器目录表里的音频条目** ∪ **`scene.json` sound 层引用的音频路径**。
两路来源都要按 §2 规范化、按 §1 过滤。

4.2 去重键 = 规范化路径。同一路径出现多次时：
- **只产出一条**记录；
- `size`：取**最后一次出现的正数**（> 0）；后续出现 0 / 未知不覆盖已有正数；
- `refs`：按出现顺序追加**引用它的层名**，同一个层名只记一次，没有层名（条目来源）不追加。

4.3 条目来源的 `size` 用容器目录表给出的**原始长度**（不是压缩后长度）。
若同路径在目录表里出现多次，**只有第一条**参与"条目头"读取（§5）。

4.4 `scene.json` sound 层的遍历：
- 从 `objects` 数组递归；每个对象可有 `objects`（子数组）；
- 对象的 `sound` 字段可以是字符串或字符串数组，取其中的字符串；
- **层名** = 该对象的 `name`，没有 `name` 时用 `id`（转成字符串）；两者都没有时不记 refs；
- `scene.json` 解析失败 / 结构异常**不得**让整次扫描失败，只当"没有引用"处理。

4.5 `scene.json` 引用了包内不存在的音频路径时：**照样列出**该条，`size = 0`
（`refs` 照记）——它代表"场景想要但包里没有"的音轨。

---

## 5. 条目头的读取

5.1 只有**提交给判定**的条目才读头字节；非音频条目**一次都不读**。

5.2 每条候选**最多读一次**头（同路径多次出现也只读第一条，见 §4.3）。

5.3 读取长度 ≤ 16 字节；容器允许"整条比 16 字节还短"（此时读实际长度）。

5.4 读头失败（条目越界、IO 错误、被截断）**不得**影响该条进入清单：
`mime` 按 §1.2 的后缀兜底，`size` 按 §4.2。

5.5 压缩条目：若条目以 LZ4 块链存储，则 `size` 必须取**块链头记录的原始长度**
（u64 小端，位于条目开头 8 字节）；判定为块链的条件（三个同时成立）：
1. 头至少 8 字节；
2. 该 8 字节**不是**任何 §3 规则的命中（真魔数优先，防止把 `ID3`/`fLaC` 之类误当长度）；
3. 头 8 字节按 u64 小端解释出的原始长度 **> 存储长度** 且 **< 2^31**。
   此时该条目的 MIME **必须**回落 §1.2 的后缀兜底（压缩字节做容器判定会给出错误结论）。

## 6. 返回结构（对外契约）

6.1 单条音轨（字段名与顺序是契约）：

```json
{ "path": "sounds/a.mp3", "size": 123456, "mime": "audio/mpeg", "refs": ["bgm-main"] }
```

- `path`：§2 规范化后的路径（字符串，非空）；
- `size`：字节数（整数 ≥ 0；未知 = 0）；
- `mime`：§3 命中值，否则 §1.2 兜底值（字符串；本模块保证表内后缀一定得到非空 MIME）；
- `refs`：引用它的 `scene.json` 层名数组（可能为空数组，顺序 = 出现顺序）。

6.2 清单按 `path` **升序**排序（按 JavaScript 字符串的码元序，确定性）；`path` 互不相同。

6.3 包内枚举返回体至少包含：
`{ tracks, headReads, sceneJsonRead }`
- `headReads`：实际发生的头读取次数（用于验证 §5.2 的"最多一次"）；
- `sceneJsonRead`：本次是否为取 refs 而读并解析了 `scene.json`。

6.4 场景级扫描（`scanSceneAudio` 一类入口）返回体至少包含：
`{ tracks, source: 'pkg' | 'dir', cacheHit, indexEntries, headReads, bytesRead }`
- 松散源：`source='dir'`、`cacheHit=false`、`bytesRead=0`；
- 包源：`indexEntries` = 目录表条目数；`cacheHit=true` 时 `headReads`/`bytesRead` 必须为 0；
- 缓存键 = `绝对路径 + mtimeMs + size`；同键第二次调用不得再读文件字节。

6.5 模块导出的稳定名字（改名 = 破坏契约）：
`scanSceneAudio`、`collectDirAudioTracks`、`pkgAudioIndexStats`、`clearPkgAudioIndexCache`。
宿主路由**必须**用 `audioMimeFor`（§3.6）取音频 content-type，不得另写嗅探或扩展名表。
内部辅助函数（后缀判定、容器判定、枚举核心、LZ4 头判定）的名字**不是**契约，
但**必须**与本规格的措辞一致（后缀表 / 容器规则表 / 枚举 / 块链判定），不得沿用其它实现的名字。

---

## 7. 明确不做的事

7.1 不做采样率/时长/声道解析——本模块只回答"有哪些音频、多大、什么容器"。
7.2 不读整条音频数据（除 `scene.json` 外，任何条目的完整字节都不进内存）。
7.3 不下载、不转码、不落盘。
7.4 不猜测 §1.2 表外后缀的 MIME。
