## 2 改造后的门禁：四个档 + 一把锁

```
bash tools/check.sh            # 默认：每步先算输入键；键未变且上次真跑为绿 ⇒ SKIP-CACHED
bash tools/check.sh --full     # 忽略缓存，12 步逐条真跑（CI / 发版 / 怀疑缓存；覆盖不丢的权威档）
bash tools/check.sh --list     # 只列 12 步与每步缓存状态（绿/红/未缓存/脏）+ 当前输入指纹；不跑判据、不抢锁
bash tools/check.sh --quick    # 老口径：跳过第 3 步（组合矩阵）
bash tools/check.sh --selftest-lock   # 门禁自身的锁自检：只抢锁/打印/退出（tools/gate-cache-test.mjs 用）
```

对外输出格式**没变**：`== N/12 <原名> ==` 12 个步骤头、结尾 `全部通过 ✓ / 存在失败项 ✗`、`exit 0/1`。
新增的是每步一行 `⏱ 第 N 步 PASS，用时 …` / `⏭ SKIP-CACHED（… 上次 …，键 ……）`，以及结尾汇总：

```
== 汇总（12 步） ==
PASS 11 / FAIL 0 / SKIP-CACHED 1（真跑 11 步，跳过 1 步）
总耗时 42.0s（真跑合计 39.3s；SKIP-CACHED 沿用上次结论、省下 2.7s）
峰值内存 ≈ 297 MiB（进程组 RSS 每 2s 采样；含共享页 ⇒ 是上界）
输入指纹 a1b2c3d4e5f6（--list 看每步状态；--full 忽略缓存逐条真跑）
```

### 2.1 缓存键 = 门禁的**输入**哈希（不是输出）

| 进键的东西 | 口径 | 为什么 |
| --- | --- | --- |
| 工作树内容 | `lib/**` + `tools/**` + `docs/**` + `package.json` + 根下其它文件，**逐文件 sha256**（内容，不是 mtime） | 改一个字节必变；`docs/**` 也进键是因为多条判据运行时校验 `docs/*.md` 的指针/阈值表（`persist-test` 直接读 `docs/PERSISTENCE.md`、`transcode-prescale-test` 读 `docs/TRANSCODE-RESOURCE.md`、`style-scope-guard` 校验 `docs/*.md:行号` 指针） |
| **排除**门禁自己的产物 | `tools/probe-out/**`（第 9 步的截图/JSON 落点）、`dist/**`（第 11 步的 bundle 产物）、`node_modules/`、`.git/`、`*.log`/`*.tmp`/编辑器残渣、软链 | 不排除的话"跑一遍门禁"自己就把键改掉 ⇒ 缓存永远命不中（有判据钉住：`A1`） |
| `git HEAD` | `git rev-parse HEAD` | 5 条判据拿 `git show HEAD:lib/client.js` 当 before（`dir-picker` / `token-namespace` / `thumb-chain` / `persist` / `bgwrap-visible`） |
| 运行时 | `node` 版本/平台/架构、`ffmpeg`/`ffprobe` 的 `-version` 首行或 `absent` | 决定转码类判据是"真跑"还是"显式 SKIP"——后来装了 ffmpeg 必须能把那部分补上 |
| 语料 | `../allwallpaper/{dd,0917}` 的 **size+mtime** 元数据（399 个文件），另含 `MPW_SCENE_ROOT` | 语料是第 2/7/8/11 步的真实输入 |
| 已装 better-sidebar | `MPW_BS_DIR`（缺省 = `os.homedir()` 下 DSH profile 里那份）的 `package.json` + `lib/*.js` 指纹 | 第 10 步读它做"锚点金丝雀"（装了/换版本/删了 ⇒ 必须重跑） |
| 步号 | 1..12 | 逐步分开缓存 |

全跳过的档实测 **2.0~3.0s**（其中 ~0.5s 算键 + ~1.4s 是 12 次 `node` 子进程启动各算一次决策 + 采样器；想再压可以把 12 次决策合并成一次调用，收益 ~1s，本轮没做）。

单次算键实测 **0.4~0.7s**（6.8MB 工作树内容哈希 + 399 条语料 stat + 两次 `-version`），12 步共用一次。

**⚠ 遍历只信 `lstat`，不信 `Dirent.d_type`**（本轮实测踩到的坑，已修 + 已加判据）：在部分虚拟/容器文件系统（overlayfs、fuse 等）下
`readdirSync(withFileTypes)` 的 d_type **两个方向都会撒谎** —— 新建目录会回 `DT_UNKNOWN`（`isFile()` 与 `isDirectory()` 同时 false），
而**普通文件会被报成 symlink**。第一版实现按 d_type 分类 ⇒ 有 4 个条目被当成软链静默跳过：

| 被漏掉的条目 | dirent 说 | lstat 说 |
| --- | --- | --- |
| `tools/theme-assist-test.mjs` | symlink | 普通文件 |
| `tools/desktop-compat-test.mjs` | symlink | 普通文件 |
| `docs/TRANSLUCENT-THEME.md` | symlink | 普通文件 |
| `../../docs/tasks/ZCODE-PROMPT-CHECK-SPEEDUP.md`（当时在插件仓 `docs/tasks/` 下） | symlink | 普通文件 |

后果是**缓存键的静默空洞**：改这两个判据脚本里任何一个，键都不变 ⇒ 该步会被误判"绿"而跳过（正是"为了快而漏判据"那条红线）。
现在改成**每个条目一次 `lstat`**（工作树 ~168 + 语料 399 个条目 ⇒ 几毫秒），并加了两条判据：`A10`（该进指纹的条目一条都不许悄悄消失）、
`A11`（dirent 谎报成 symlink 的普通文件仍必须判成 file）。本仓同类先例：`lib/index.js` 的 `listWallpaperFiles` 也栽在 d_type 上。

### 2.2 "跳过"只有一个出口（覆盖不丢的红线）

```
skip ⟺（键完全相同）∧（上次是**真跑**）∧（那次退出码 0）∧（不是 --full）
```

- 键变了 / 上次红 / 没有记录 / `--full` ⇒ **一律真跑**；
- 缓存自己坏了（记录读不出、JSON 半截、schema 不认识、步号对不上、键算不出、记录写不进）⇒ **绝不报绿**：当没缓存真跑，并在汇总里 `⚠ 缓存降级 N 次` 显式记账；
- 每条"绿"记录里存着**上次真跑的耗时**，`SKIP-CACHED` 行与 `--list` 都把它打出来（跳过 = 沿用某次真跑的结论，不是"没跑过"）。

### 2.3 单实例锁

- 优先 `flock`（本机有）：`exec 9>>锁文件` + `flock -n 9`，锁文件里写 `PID` + 起始时间戳（**抢到之后**才写，抢不到不许动别人的字）；内核在进程退出时释放 ⇒ 没有"残留锁"这回事。
- 没有 `flock` 的机器退回 `mkdir` 原子锁（info 文件同格式；只有"PID 确定已死"才清残留，拿不准就快速失败）。
- 抢不到 ⇒ 人话提示 + `exit 2`（**非零**，调用方能区分"没跑"与"跑了但失败"）：

```
✗ 另一个门禁在跑（PID 12345，已跑 87 秒），本次退出 —— 没有跑任何判据。
  原因：同一时刻只允许一个门禁实例（两条线并发跑会让内存翻倍，本机就是被这个跑崩的）。
  锁文件: <os.tmpdir() 下的路径>
  怎么办：等那一个跑完再跑。锁由 flock 交给内核管，进程退出即释放 ⇒ 不会留"残留锁"；
          只想看状态可以另开终端跑 bash tools/check.sh --list（它不抢锁、不跑判据）。
```

- `--list` 不抢锁（锁被占着也能看状态；`tools/gate-cache-test.mjs` 的 C1 钉住）。
- 踩过的坑（已修 + 已加判据）：内存采样子壳会**继承锁 fd**，门禁退出后它（和它的 `sleep`）还会把锁多握 ≤2s ⇒ 紧接着的第二次调用被误判"另一个门禁在跑"。现在采样器 `exec 9>&-` + 输出接 `/dev/null`，`cleanup` 里 `kill -9` 并 `wait`。

### 2.4 峰值内存汇总

门禁自己每 2s 采一次**本进程组**的 RSS 之和（`ps -eo pgid=,rss=`），结尾打印 `峰值内存 ≈ N MiB（进程组 RSS 每 2s 采样；含共享页 ⇒ 是上界）`；`ps` 不可用时如实写"不可测"，不瞎报。全跳过的运行几乎不分配内存（编排自检实测 ~19 MiB）。

## 4 消掉第 2 步的 146s 白等（`frost-rail-test`）

**根因**（基线 gap 分析 + 代码定位）：`tools/frost-rail-test.mjs` 的 PART 2 有 12 个 scenario，每个 scenario 起一个子进程
（`execFileSync(..., '--child', sc)`）。子进程把该 scenario 的 ✓/✗ 全部打印完之后，**插件挂载时排的 12s"补挂校验"定时器还挂在事件循环上**
（`_stub.mjs` 注入的定时器走的是真 `globalThis.setTimeout`）⇒ node 退不出去，白白多活 12.2s × 12 = **146s**。

**修法**（只改 `tools/**`，不碰 `lib/**`，不碰任何断言）：

- `tools/_stub.mjs`：新增导出 `cancelWorldTimers()`（= 既有语义"世界换代 / 页面随文档消失"的 `world.cancelAll()`；**纯新增**，现有调用方零影响）；
- `tools/frost-rail-test.mjs`：`--child` 分支在 `await runChild(sc)` **之后**调用它。

**为什么这不改判据**：取消发生在 `runChild` 返回之后 ⇒ 该 scenario 的 ✓/✗ 与交给父进程的 `__RESULT__{…}` 都已经产出，一个字节都不改。
验证方式：同一份 `lib/client.js` 下，用**临时**开关 `MPW_FROST_KEEP_TIMERS=1` 跑"保留定时器（= 改动前行为）"，再跑"取消定时器（= 改动后）"，两次输出**逐字节对照**（脚本每次跑完都比对 `lib/client.js` 的 sha256，中途被并发改动就整轮重来；**开关本身已在对照完成后从代码里删掉**，最终代码 = A/B 里的"取消"那一档，去掉开关后又跑了一次确认输出不变）。

| 模式 | 耗时 | 输出 |
| --- | --- | --- |
| 保留 12s 定时器（改动前行为） | 150.1s | 见 §4.1 |
| 取消定时器（改动后） | **4.7s** | **与上一行逐字节相同**（含全部 ✓/✗ 行） |

另有一次独立复测：单条脚本 **150.0s → 3.4s**（同一份 `client.js`，232 ✓ / 0 ✗）。按第 2 步 508s 计，整跑应从 851s 降到 ~705s（§6 验收回填实测）。

## 7 诚实边界与已知限制

1. **语料指纹是 size+mtime，不是内容哈希**：语料 24GB，内容哈希不现实。理论上"内容变了但 size 与 mtime 都没变"这一档不进键 ⇒ 那种情况用 `--full` 兜底。语料（`allwallpaper/{dd,0917}`，399 文件）不在仓库里。
2. **`docs/**` 进键是保守选择**：改一次文档 ⇒ 下次默认档 12 步全真跑一遍。理由是判据会运行时校验文档指针/阈值表（§2.1）。想省这一次，改完文档直接跑 `--full`（发版前本来就要 `--full`）。
3. **锁 fd 会被子进程继承**：门禁在跑时它的子进程都持有锁 fd（无妨）；若某个子进程**没被回收**（罕见：崩溃残留的浏览器/子进程），锁会跟着它多活一会儿，此时第二次调用会看到 `另一个门禁在跑`（提示里会写"记录里的 PID 已经退出"）。这是**故意保守**：flock 是权威判据，绝不"猜着跑"。
4. **`--quick` 与缓存**：`--quick` 不跑第 3 步，也**不读写**第 3 步的缓存（不会把"没跑"记成"绿"）。
5. **并行**：本轮**故意不并行**跑重活（内存会更炸）。可并行的只有"在睡觉的脚本"，但那要把门禁改成作业调度器，收益/风险不划算（§5）。
6. **`--list` 的"上次真跑"时间是最后一次真跑**，不是最后一次跳过；跳过的运行不刷新记录（这样才看得出"这条结论是哪次真跑得到的"）。
7. **缓存与锁都在 `os.tmpdir()`**，仓库里不写本机绝对路径；可用 `MPW_GATE_CACHE` / `MPW_GATE_LOCK` 覆盖（测试就用它做隔离）。
