# 扫描页缩略图 OOM 风险清单与防护（2026-10-25 任务 1.2）

> 范围：侧栏「壁纸」页签 →「扫描壁纸」内部 tab 的大容器网格墙。
> 判据：`node tools/thumb-sched-test.mjs`（29 条，含 5 条变异自证）。
> 机制代码：`lib/client.js` 的 `MPW-THUMB-SCHED` 块（模块级调度器）+ `mpwThumbChildren` 的
> `sched` 档 + `mpwThumbOk/mpwThumbNext/mpwThumbFail` 的调度钩子。

## 1. 风险清单（风险点 / 触发条件 / 防护措施）

| # | 风险点 | 触发条件 | 防护措施（现状） |
|---|---|---|---|
| R1 | 并发请求/解码风暴：滚动长库时网格持续挂载新条目，每条 `<img>`/`<video>` 同时发请求、同时 decode | 库 > 一屏（懒加载每页 24 项仍会累计到数百） | **并发上限**：受管元素带 src 在途 ≤ N（默认 4；档键 `thumbMaxConcurrency` 可配 1..8），队列 FIFO + 槽位释放即续（`mpwThumbSchedPump`） |
| R2 | 离屏位图滞留：列表全部保持挂载，滚过的缩略图解码位图不释放 | 用户滚过大量条目 | **视口释放**：IntersectionObserver 观察缩略框，离屏 ⇒ `removeAttribute("src")`（视频再 `load()` 复位）⇒ 浏览器释放解码位图；回屏从候选链当前下标续载（HTTP 缓存兜底） |
| R3 | 视频首帧解码堆积：`<video preload=metadata>` 每个持一个解码器 | 列表含大量视频档 | 双重收口：① 视频元素同受并发上限与视口释放管；② **standby 延迟起载**——图候选（preview.gif 等）没耗尽前视频不派 src，维持"优先现成预览图、抽帧退兜底"的既有优先级 |
| R4 | 失败候选挂死占槽/无限重试 | 宿主慢/容器坏/URL 失效 | **超时推进**：在途 15s 无响应按失败推进候选链（换候选重新武装超时）；候选耗尽 ⇒ 判死走占位；**重试一次上限**（整链失败后仅回屏重试一次，再败即终局占位） |
| R5 | 重入口重复走整条候选链（重复请求/重复 decode） | 离屏释放后回屏 | **重入口 LRU**：item → 最近成功候选下标；条目 ≤ 300 且估算字节 ≤ 64 MB 双上限，超限淘汰最旧 |
| R6 | 大图整幅 decode（原图直接进列表） | 作者嵌入高分辨率 preview（如 4K jpg ≈ 33MB 位图/张） | **部分缓解**：并发上限 + 视口释放把"同时活着的位图"钉在 N 张量级；单图 >2MP 计数（`oversize`）可观测。**服务端缩略/canvas 降采样未做**（见 §3 未验/待裁决） |
| R7 | 堆增长无感知 | 长会话 + 大库 | **可观测 + 自动降档**：每 20 次起载采样 `performance.memory.usedJSHeapSize`（可用时），超 384MB 自动把并发降到 2（只降一次）并打日志；计数器（started/done/released/timeouts/retries/oversize）经 `globalThis.__mpwThumbSched.stats()` 可读 |

## 2. 固化判据（能失败 + 变异自证）

- C1 并发不超限：kick 30 ⇒ 在途恰为 4、FIFO 续泵（变异 M-conc：上限 100 ⇒ 红）
- C2 滚出视口会释放：release 必真摘 src，视频 `load()` 复位，槽位归还（变异 M-release：不摘 src ⇒ 红）
- C3 超时推进：15s 超时换下一候选，耗尽判死让槽（变异 M-timeout ⇒ 红）
- C4 缓存不超限：LRU 300 条 / 64MB 双上限淘汰最旧（变异 M-lru ⇒ 红）
- C5 重试一次上限：再败即终局摘 src + 占位（变异 M-retry ⇒ 红）
- C6 自动降档：堆超阈值 ⇒ 并发 4→2（一次性）
- C7 非受管不变：设置页网格（无 queued 标记）零影响
- C8 standby 提升次序不变：图候选耗尽才起载视频首帧

## 3. 边界与未验（诚实声明）

- **尺寸上限只有"部分缓解"**：服务端缩略路由（需图像解码库）与 canvas/createImageBitmap
  降采样（需改 `<img>` 候选链架构）本轮未实现；单图解码像素上限当前靠"并发 × 视口"间接约束，
  >2MP 计数只用于观测。
- **LRU 缓的是元数据（候选下标），不是解码位图**：位图内存由视口释放 + 并发上限控制；
  64MB 字节上限按条目估算字节计（URL 串 ×2 + 96B），防的是元数据表无界，不是位图。
- `performance.memory` 是 Chromium 系 API；Firefox 上不可用 ⇒ 采样静默跳过（降档不触发）。
- 真机（浏览器）实测读数（真实堆曲线、释放前后内存差）**未测** —— 本轮禁浏览器门禁。
- 视口释放以 IntersectionObserver 为准；宿主若在不支持 IO 的环境（理论），回退为
  "只 kick 不释放"（行为等同改前，但不超并发上限）。
